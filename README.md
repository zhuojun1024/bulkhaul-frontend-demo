# 大宗物流综合管理平台（BulkHaul Frontend Demo）

纯前端（Vue 3）大宗物流全链路业务演示系统。覆盖 **合同 → 计划 → 调度 → 在途执行 → 异常 → 结算 → 对账 → 开票 → 收款 → 单证 → 报表** 的完整业务闭环，并内置客户门户、司机端（H5）、安全/保险、仓储、消息中心与 RBAC 权限体系。

所有业务逻辑集中在 mock 服务层（`src/mock/flow.js`），按"可平移为后端 endpoint"的标准设计：状态机守卫、RBAC 单点校验、乐观锁、审计日志、定时任务模拟均在此层实现，视图层只读展示 + 调用服务层。

### 关键设计决策

1. **RBAC 四层权限，默认拒绝**
   - 菜单级：`ROLE_MENUS` 控制侧边栏可见菜单与路由访问（路由守卫强制）；
   - 按钮级：`ROLE_ACTIONS` 操作码控制关键操作按钮显隐（`usePerm().can()`）；
   - 服务层单点校验：`requireAction` 在每个写操作入口按操作人角色校验——前端按钮权限仅为体验层，改 localStorage 也无法绕过；
   - 行级数据权限：`dataScopes` 按装货侧场站区域过滤列表（如调度员仅见华北线路）。
   - 权限表数据化：`db.rolePerms` 可在角色管理页编辑并持久化，运行时优先于内置表；未注册角色（含空角色）一律拒绝。

2. **调度单状态机（执行核心）**

   ```
   pending 待装货 → loading 装货中 → intransit 在途 → unloading 卸货中 → completed 已完成
        │               │                │  ▲
        │  任意执行态可上报异常 ↓          │  │ 异常关闭后恢复运输
        └──────────────→ exception 异常 ─┘
   ```

   - 公路车次（公路/多式联运）占车辆/司机、进出场站过磅；铁路/水运/管道按运输单元执行（车号/船名/管段），不占车辆、无公路磅单；
   - 装货前可**取消**（释放占用）或**改派**（换车/换司机，目标须空闲/证照未过期/无其他未完结车次，换司机需重新接单）；
   - PC 端与司机端入口共用同一状态机核心（`doConfirmLoad` 等），司机端走独立身份守卫（车次本人司机），不做 PC 端 RBAC——等价后端司机 App 独立鉴权。

3. **联动回卷（自底向上对齐）**
   调度单状态变化 → 回卷计划进度（已完成车次运量/批次量）→ 回卷合同进度（实际完成运量/合同计划量）；完成/取消时占用/释放车辆与司机。仓储联动：确认装货按入库时间 FIFO 跨批次出库（可发库存不足拦截装货），确认卸货按出磅净重入库生成新批次。

4. **并发控制（乐观锁）**
   车辆/司机带 `version` 字段，派车采用两阶段提交：先校验全部资源（`validateResourceCommit` 提交前二次校验），全成或全滚，杜绝"半套"调度单。

5. **定时任务模拟（后端 cron 等价物）**
   `scheduler.js` 全局 3s tick，独立于页面生命周期：GPS 遥测推进在途进度 → 电子围栏事件（轨迹偏离/超 ETA 自动生成异常单）→ 逾期校准 → 异常升级（待受理超 2h 升级提醒、超 8h 督办）→ 合同审批催办（超 24h）。UI 通过 `onSchedulerEvent` 订阅，对接后等价 WebSocket 推送。

6. **登录安全**
   图形验证码（一次性、60s 有效、SVG 渲染）+ 密码 SHA-256 哈希存储（不落明文）+ 连续 5 次失败锁定 5 分钟；未登录直调服务层按"未登录"态默认拒绝；登出清除服务层 operator（审计日志不记在旧用户名下）。

7. **消息中心**
   关键业务事件驱动（审批/调度/异常/结算/需求/系统），按 RBAC 操作码定向到目标角色（审批消息只发审批人）；支持免打扰（时段 + 类型屏蔽，跨零点）；未读角标。

8. **数据持久化**
   种子数据加载后恢复同版本 localStorage 快照（刷新不丢数据）；深度监听 db 防抖 800ms 写快照；快照带版本号与写入时间戳（多标签页冲突时跳过写入避免静默覆盖）；日志/消息设上限（1000/500）防 5MB 配额撑爆。

9. **确定性种子数据**
   全局 `mulberry32(20260815)` 固定种子，刷新数据一致；跨域派生数据（运价表/客户需求/司机评分）使用独立随机源，不扰动全局序列；皮重/装货差异等按 ID 确定性派生，种子与运行时共用同一口径。

10. **设计系统**
    设计令牌（CSS 自定义属性）单一来源：`tokens.css`（原始色阶 → 语义令牌）→ `index.css`（Element Plus 主题映射）→ `useTokens()`（JS/ECharts 场景）→ `design-tokens.json`（Figma 工具链）。WCAG AA 对比度校验，详见 [docs/design-system.md](docs/design-system.md)。侧边栏为自研浅色菜单组件 `AppMenu`（手风琴/收起态弹层/键盘导航/动效降级）。

## 业务流程

### 主链路（收入侧闭环）

```
客户门户发起运输需求 ──→ 销售转为合同草稿
                              │
              合同审批链（提交 → 逐级审批 → 通过/驳回；改价/延期/终止走变更审批）
                              │
              按合同生成运输计划（批次拆分）→ 派车（两阶段提交，占车辆/司机）
                              │
        执行：司机接单 → 扫码确认装货（进磅过磅 + 仓储 FIFO 出库）
              → 发车（在途监控：GPS 轨迹 + 电子围栏）
              → 到达 → 扫码确认卸货（出磅过磅 + 仓储入库 + 电子签收）
                              │
        任意环节可上报异常（PC 端/司机端 H5）→ 异常单（受理 → 处置 → 关闭/恢复原状态，可升级督办；
        事故类联动事故记录 → 保险理赔：报险 → 责任认定 → 结案冲减损失）
                              │
        结算：生成账单（出磅净重 × 快照单价 − 损耗/质量扣重 − 异常损失）
              → 三方对账（差异检测：装货差异/损耗/质量扣重）
              → 客户确认 / 异议（门户；异议回待对账）
              → 确认结算 → 收款（含预付款抵扣 / 银行流水自动核销 / 收款冲正）
              → 逾期催收（提醒 → 正式催收 → 法务函）
                              │
        开票（票款一致拦截：金额变化须红冲重开）
                              │
        单证归档（磅单/签收单/调度单/质检报告/对账单/发票 6 类）→ 报表中心（5 类）
```

### 成本侧闭环

公路车次完成即自动生成趟次应付（司机趟次费 + 外协车运费）→ 付款核销（`payables` 台账），结算页"趟次应付"页签管理。

### 辅助流程

- **客户门户**：发起运输需求（pending → 转合同 / 驳回）、我的合同/账单、确认或异议对账（账单可展开逐车次对账明细：进磅/出磅/结算量/损耗/质量扣重/差异）；
- **司机端（H5）**：接单 → 扫码装货/卸货（装卸码校验）→ 发车/到达 → 电子签收（支持补签）→ 收入明细；执行中可上报异常（事故/故障第一知情人，走独立身份守卫）；
- **安全管理**：事故登记/关闭、安全培训（参训司机）、车辆安全检查、年检/驾照过期拦截派车；
- **仓储管理**：批次库存（FIFO 出库）、手工入库/补库（采购到货，RBAC 守卫 + 容量校验）、仓库新增/编辑（RBAC 守卫 + 容量下限校验）、安全库存预警（跌破下限定向通知）、库存状态（normal/locked/临期）；
- **场站管理**：场站新增/编辑（RBAC 守卫 + 名称查重），绑定配套仓库后装卸货联动仓储出入库；
- **银行核销**：银行流水录入（客户已转账未登记，RBAC 守卫）→ 待核销 → 自动核销（金额=账单未付余额）/ 手动核销，闭合"流水从哪来"链路；
- **运价管理**：线路运价表（商品 × 装/卸场站 × 方式），合同新建可查表取价、调价留痕、启停；
- **系统管理**：用户（含数据范围设置/重置密码）/ 角色（菜单 + 操作授权，数据化权限表）/ 操作日志（全量审计）。

## 定位说明

本项目为**演示/方案展示**定位：整个 `db` 与校验逻辑在浏览器端，真实安全需后端承接。服务层按"对接后端时函数即 endpoint 校验逻辑"的标准编写（RBAC 单点校验、乐观锁、ID 生成、登录鉴权均已按后端口径实现），可作为后端接口设计的直接参照。
