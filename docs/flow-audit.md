## 二、总体结论

**作为"可演示的闭环"：成立，且第一轮 P0/P1/P2 缺陷已全部修复。** 主链路端到端可跑通，异常/仓储/安全/司机端/客户门户/成本侧均有真实联动，不是"页面孤岛"。

**作为"对接接口后能真实闭环的产品"：架构合格，但仍存在 5 个流程逻辑断点 + 一批产品完整度缺口 + 若干"必须下沉后端"的架构点。** 不处理，闭环会在这些位置于真实环境断裂。

**最大底气**：`src/mock/flow.js` 已是一个设计良好的**服务层**——所有状态流转集中、带前置守卫、带审计日志、带回卷联动，可一对一映射为后端 endpoint。这是本项目对接 API 迁移成本可控的根本原因。

主链路（已实测跑通）：

```
合同(草稿→部门审批→公司审批→执行) → 拆批计划(信用/剩余量校验)
→ 派车(车辆司机互斥+司机接单) → 装货(扫码+进磅+仓库出库)
→ 在途(围栏事件) → 卸货(扫码+出磅+仓库入库+电子签收)
→ 结算(生成→三方对账→客户确认→确认结算→收款→逾期) → 开票(红冲/重开)
```

## 三、闭环断点（流程逻辑层，P0）

| # | 级别 | 问题 | 状态 |
|---|------|------|------|
| N1 | ⚠️ | **客户确认对账不是结算闸门**：`confirmSettle` 不校验 `customerConfirmed`，结算专员可在客户未确认时直接确认结算，"客户确认"步骤形同虚设，闭环缺客户这一端的真实约束 | ✅ 已修（2026-08-16，`confirmSettle` 增加客户确认硬闸门，未确认返回错误；结算详情/列表确认弹窗同步提示"客户尚未确认"） |
| N2 | ⚠️ | **电子签收非强制收货凭证**：PC 端 `confirmUnload` 无签收直接完成；结算/对账全程不引用 `receipt`，签收单仅展示。大宗物流以签收为收货依据，当前可"无签收结算" | ✅ 已修（2026-08-16，对账明细 `buildReconciliation` 逐车次带 `hasReceipt`（公路须签收、非公路不适用），对账表增"签收"列，结算确认弹窗对无签收公路车次强提示。硬拦截（无签收不可结算 + 补签收入口）列为 P1） |
| N3 | 🐛 | **合同改价追溯已执行车次**：结算用合同**当前** `unitPrice`（`calcSettlementFees`），而车次 `fee` 用建计划时快照价 → 执行中改价后结算额 ≠ 车次费用之和，对账必出"差异" | ✅ 已修（2026-08-16，派车时写入车次快照单价 `d.unitPrice`（种子+运行时），`calcSettlementFees` 改按车次快照单价逐车次计算运费/损耗扣减，合同改价不追溯已派车车次） |
| N4 | 🐛 | **合同完成无容差、无手动关单**：种子合同量=计划总量×1.1~1.3（`plan.js:41` 回填），全部计划完成也仅到 ~77-91%；拆批取整累积缺口还会卡 99%。无"合同完结"手动入口，"合同完成→归档"演示中几乎不可达 | ✅ 已修（2026-08-16，新增 `completeContract` 手动完结（守卫：执行中 + 未取消计划全部完成），合同详情/列表"合同完结"按钮（计划全部完成时可用），完结后进度置 100% 可归档） |
| N5 | 🐛 | **`issueInvoice`（结算详情入口）无状态守卫**，与发票管理页 `issueInvoiceRow`（有守卫）口径不一致，双击可重复开票、一账单多发票 | ✅ 已修（2026-08-16，`issueInvoice` 增加"未开票"状态守卫，与 `issueInvoiceRow` 同口径；结算详情开票调用处理守卫错误） |

> 口径决策：N1 客户确认设为**硬闸门**（对接后真实闭环需要客户端真实约束）；N2 签收本轮做**可见化+强提示**（硬拦截涉及非公路豁免与补签收入口，列 P1）；N3 改价**不追溯**已派车车次（按车次快照价结算）。

## 五、对接 API 的关键点（决定"能否真实闭环"，P2 前提）

以下逻辑当前**跑在前端**，对接后必须下沉后端，否则真实环境闭环断裂：

| 当前实现 | 问题 | 对接后应为 |
|---|------|-----------|
| 围栏事件由监控页 3s tick 触发（`track/index.vue:473`） | **页面不开就不产生围栏异常** | 后端定时任务 |
| 监控页 tick 直接改 `db.progress/speed` | UI 在改业务数据 | 后端 GPS/遥测数据源 |
| 逾期状态仅 `recordPayment`/页面加载时重算 | 应用关闭期间不会标逾期 | 后端定时任务 |
| 车辆/司机占用是前端 busy 检查 | 无并发控制，双人同时派车会超占 | 后端事务/乐观锁 |
| RBAC + 状态机守卫全在前端 | 改 localStorage 即绕过 | 后端单点校验（前端守卫保留作体验层） |
| 看板/报表前端全量聚合（`dashboard.js`/`report.js`） | 数据量大不可行 | 后端聚合接口 |
| ID 按数组长度派生（`PD-00001`） | 并发/删除后冲突 | 后端正规 ID 生成 |

**可保留前端**：表单校验、交互、展示。**数据模型**可直接以 `src/mock/persist.js` 快照结构为雏形。`flow.js` 每个导出函数 ≈ 一个后端 endpoint。

## 八、验收路径（端到端演示脚本，回归用）

正向主链路，任何一步卡住即为断点：

```
新建合同 → 提交审批 → 部门审批 → 公司审批 → 拆批计划 → 调度派车
→ 司机接单 → 扫码确认装货(进磅) → 发车 → 在途推进(围栏) → 到达
→ 扫码确认卸货(出磅) → 电子签收 → 生成结算单 → 对账 → 客户确认对账
→ 确认结算 → 收款 → 开票
```

反向验证异常闭环：

```
上报异常(含事故类) → 受理指派 → 处置完成 → 关闭归档(损失补扣结算)
→ 调度单恢复运输 → 事故记录结案
```

权限回归：

```
只读用户登录 → 菜单/按钮只读 → 直改 URL 访问受限页被拦截
新建角色 → 默认无任何菜单(deny) → 授权后按授权显示
停用账号 → 该用户刷新后无法访问任何业务页
```
